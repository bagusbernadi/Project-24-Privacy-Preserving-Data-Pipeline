Project 24: Privacy-Preserving Data Sharing Pipeline

Tujuan project: membangun pipeline yang menyamarkan identitas di data produksi (nama operator, kode lot, customer, catatan bebas) dengan metode yang sesuai tiap jenis kolom, lalu membuktikan dengan angka bahwa risiko identifikasi ulang turun sementara hasil analisis (KPI, ranking, Pareto) tetap sama, sehingga data bisa dibagikan ke pihak luar dengan aman.

Kategori:Rancangan projectPerakitan sepeda motorData simulasi (identitas palsu)Python + anonymization

Project Introduction

Bayangkan sekolah yang ingin mengumumkan hasil ujian di papan pengumuman. Nama siswa diganti nomor peserta, dan hanya wali kelas yang memegang daftar nomor dan nama. Tanggal lahir cukup ditulis tahunnya. Catatan pribadi guru tentang siswa dihapus. Pengunjung tetap bisa melihat kelas mana yang nilainya paling tinggi, tetapi tidak bisa menebak nilai siswa tertentu.

Masalahnya, kadang satu siswa tetap mudah ditebak. Misalnya hanya ada satu siswa kidal di kelas 3B yang lahir tahun 2010. Karena itu, setelah disamarkan, data perlu diuji: masih adakah baris yang terlalu unik?

Project ini membangun pipeline anonymization: setiap kolom diklasifikasi, diberi perlakuan yang sesuai, lalu hasilnya diuji dari dua sisi, yaitu risiko dan kegunaan. Datanya adalah data simulasi dengan identitas palsu karena data pabrik bersifat rahasia. Kata bergaris bawah putus-putus kuning bisa diklik untuk melihat artinya.

1. BackgroundKenapa tema ini dipilih

Latar belakang masalah

Data operasional sering perlu dibagikan ke vendor, tim lain, atau dipakai untuk portofolio. Di dalamnya ada nama operator, kode lot, nama customer, dan catatan bebas. Akibatnya:

  • Data dianonimkan manual di Excel dengan cara yang berbeda-beda, dan kolom sensitif bisa terlewat.
  • Menghapus nama saja belum cukup: kombinasi tanggal, shift, dan stasiun bisa menunjuk satu orang tertentu.
  • Penyamaran yang terlalu keras merusak data, sehingga analisis penerima menjadi salah.
  • Tidak ada bukti tertulis bahwa data yang dibagikan aman dan tetap berguna.

Alasan memilih tema ini sebagai portofolio

  • Dekat dengan kebutuhan nyata. Setiap project portofolio berbasis data kerja butuh versi anonim yang aman. Pipeline ini dipakai langsung untuk project lain.
  • Menunjukkan skill tata kelola data. Klasifikasi data, metode anonymization, uji risiko (k-anonymity), uji utilitas, dan pengelolaan kunci rahasia.
  • Tingkat kesulitan menengah. Metodenya tidak rumit, tetapi trade-off risiko dan kegunaan harus dibuktikan dengan angka.
  • Menjadi alat bantu project lain. Bisa membuat versi anonim data untuk Project 3, Project 19, Project 25, dan project manufaktur lain di portofolio ini.

4. DatasetData produksi simulasi dengan identitas palsu buatan Faker

Kenapa data simulasi? Menguji anonymization dengan data asli justru berisiko. Program Python membuat data produksi dengan struktur Project 3, lalu menambahkan identitas palsu (nama operator, nomor karyawan, nama customer, nomor telepon) memakai Faker. Kebocoran sengaja ditanam agar pipeline bisa diuji.

Ukuran: 10 stasiun, 3 model, 2 shift, ±25 operator, sekitar 75 hari kerja. Perkiraan ±4.500 baris produksi harian. Jumlah pastinya baru diketahui setelah data dibuat.

Sumber data: data simulasi buatan sendiri, dibuat oleh skrip scripts/generate_data.py dengan library Faker (Versi: v1, rancangan; Tanggal dibuat: saat Tahap B dikerjakan). Tidak memakai data perusahaan. Jika kelak dipakai pada data kerja, izin perusahaan dicek terlebih dahulu.

Fakta yang sengaja ditanam (ground truth)

1. Satu operator menjadi satu-satunya orang di shift malam pada satu stasiun, sehingga mudah ditebak walau namanya disamarkan.

2. Nama operator dan nomor telepon terselip di kolom catatan bebas pada ±2% baris.

3. Nama customer muncul di kode lot pada beberapa model khusus.

4. Satu stasiun dibuat paling sering NG, untuk menguji apakah ranking tetap sama setelah anonymization.

5. Sekitar 2–3% data kotor: nama dengan spasi ekstra atau huruf besar-kecil berbeda, yang bisa membuat satu orang mendapat dua kode samaran.

5. ToolsAlat yang dipakai dan alasannya

Python (pandas, hashlib/hmac)

Menjalankan kebijakan per kolom: HMAC-SHA256 untuk pseudonymization, generalisasi tanggal, skala angka, dan pembersihan teks.

Library bawaan Python sudah cukup. Kunci rahasia dibaca dari environment, tidak ditulis di kode.

Faker

Membuat nama, nomor karyawan, nomor telepon, dan nama customer palsu yang realistis.

Data uji terlihat nyata tanpa memakai identitas orang sungguhan.

DuckDB + SQL

Menghitung KPI, ranking, dan Pareto pada data asli dan data anonim, serta menghitung jumlah baris unik per kombinasi quasi-identifier.

Perbandingan sebelum dan sesudah memakai query yang sama persis.

pytest

Tes otomatis: tidak ada nama asli tersisa, hasil deterministik, mapping key bisa dipulihkan.

Membuktikan pipeline aman setiap kali kode diubah.

Streamlit + Plotly

Dashboard data asli vs data anonim, kurva risiko vs utilitas, dan tabel trade-off metode.

Bisa dibuka lewat link. Dashboard publik hanya menampilkan data simulasi.

GitHub + Markdown

Menyimpan kode, kebijakan kolom, dan README. File .gitignore mencegah data asli dan mapping key ikut ter-commit.

Standar industri untuk portofolio.

9. Assumptions & LimitationsKomponen tambahanKeputusan yang sudah diambil dan hal yang perlu diwaspadai

Jenis data: simulasi dengan identitas palsu Sudah Anda setujui

Data produksi dibuat program dengan struktur Project 3, ditambah identitas palsu dari Faker. Tidak ada data orang sungguhan.

Konteks: perakitan sepeda motor Sudah Anda setujui

Halaman publik memakai lini perakitan sepeda motor dengan 10 stasiun dan 3 model. Struktur tabel tetap sama dengan Project 3.

Tools: DuckDB + Streamlit Sudah Anda setujui

Konsisten dengan project lain. Tools khusus dari daftar portofolio (hashlib/hmac, Faker, pytest) tetap dipakai.

Ruang lingkup Usulan awal

Data tabel terstruktur saja, belum termasuk gambar, PDF, atau dokumen. Satu kunci HMAC untuk satu periode berbagi data. Belum memakai differential privacy. Tingkat kesulitan: menengah.

Hal yang perlu diwaspadai Usulan awal

Pseudonymization berbeda dari mapping key. Kode HMAC tidak bisa dibalik tanpa kunci, sedangkan mapping key memang dibuat untuk bisa dibalik. Keduanya disimpan dan diperlakukan berbeda.

Skala angka bukan keamanan penuh. Indeks hanya menyamarkan nilai absolut. Jika penerima tahu satu nilai asli, nilai lain bisa dihitung.

Anonim di sini belum tentu anonim di tempat lain. Data yang aman sendirian bisa berisiko jika digabung dengan data lain milik penerima.

Aturan perusahaan tetap berlaku. Pipeline membantu teknisnya, tetapi izin berbagi data kerja tetap harus diminta.

2.2 Risiko identifikasi ulang Q2, Q3, Q4

Q2
Berapa persen baris yang unik pada kombinasi quasi-identifier sebelum dan sesudah anonymization?
Utama · Terjawab dengan catatan

Pada kombinasi terketat (tanggal, shift, stasiun, model, operator), 100% baris unik di data asli; sesudah tanggal menjadi minggu dan nama menjadi kode, 0% baris unik dan k minimum 5 (target minimal 5). Nilai k sama dengan jumlah hari kerja dalam satu minggu karena satu baris per hari per kombinasi dan operator bergilir tiap minggu. Catatan: k hanya mengukur kombinasi yang dipilih. Satu sel yang dikerjakan satu orang (Performance Test (Dyno), Shift 2) menunjuk orangnya langsung dari stasiun dan shift, jadi kode operator di 225 baris sel itu ditutup. Pihak yang memegang daftar jaga mingguan lengkap masih bisa menyambungkan 38 dari 39 kode ke orangnya (97,4%); k tidak mengukur serangan semacam ini.

Q3
Apakah nama operator bisa ditebak dari kode samaran, misalnya dengan mencoba daftar nama umum?
Utama · Terjawab

Tidak, selama memakai kunci. Penyerang yang memegang 19.462 nama kandidat (nama umum ditambah seluruh nama karyawan) memulihkan 100% nama dari hash SHA-256 tanpa kunci, tetapi 0% dari kode HMAC dengan kunci rahasia, baik dengan hash biasa maupun dengan 6 kunci tebakan yang umum. Ini berlaku selama kunci panjang dan acak; kunci yang bisa ditebak membuat HMAC sama lemahnya dengan hash biasa.

Q4
Apakah catatan bebas masih mengandung nama atau nomor telepon setelah dibersihkan?
Pendukung · Terjawab dengan catatan

Tidak, dengan cara allowlist. Dari 4.500 catatan, 142 memuat nama, telepon, atau customer. Pembersihan regex (telepon, nama lengkap, dan customer yang dikenal) masih menyisakan 21 catatan karena nama depan saja atau penulisan lain lolos. Allowlist (hanya frasa aman yang dipertahankan) menyisakan 0, dengan harga 142 catatan (3,2%) berubah menjadi [dihapus]. Catatan: pemindai mencari nama yang ada di daftar karyawan dan customer, jadi nama orang di luar daftar tidak akan ditemukan; allowlist tetap aman karena menolak semua teks yang tidak dikenal.

2.5 Metode, trade-off, dan deterministik Q8, Q9

Q8
Metode mana yang cocok untuk tiap tipe kolom, dan apa trade-off-nya?
Utama · Terjawab

Tiap tipe kolom punya metode berbeda (Tabel 2.5a). Nama operator: HMAC dengan kunci, karena hash biasa dipecahkan 100%. Kode lot: mapping key, karena harus bisa dibalik oleh pemilik data. Tanggal: minggu. Jumlah: indeks, tetapi ini bukan pengaman penuh, sebab bila satu nilai asli diketahui, 100% nilai lain terhitung. Teks bebas: allowlist, bukan regex. Sel dengan satu operator: tutup kodenya. Setiap metode mengorbankan sesuatu yang berbeda: kemampuan analisis per customer, resolusi harian, atau 3,2% catatan.

Q9
Apakah pipeline menghasilkan output yang sama persis jika dijalankan ulang dengan kunci yang sama?
Pendukung · Terjawab

Ya. Dua kali jalan dengan kunci yang sama menghasilkan file anonim dengan SHA-256 yang sama (2 dari 2 file) dan mapping key yang sama. Dengan kunci lain, seluruh 4.275 kode operator berubah tetapi yield lini tetap sama. Syaratnya kunci sama: pengguna yang mengganti kunci mendapat kode berbeda, jadi kunci satu periode berbagi harus disimpan.

7. KesimpulanHasil analisis, Impact, success criteria, rekomendasi, saran perbaikan, dan batasan

7.1 Hasil analisis: jawaban atas pertanyaan utama

Bagaimana membagikan data operasional ke pihak luar tanpa membocorkan identitas, sementara hasil analisisnya tetap sama?

  • Identitas tertutup: lima metode dipakai sesuai tipe kolom. Pada kombinasi terketat, baris unik turun dari 100% ke 0%, k minimum naik dari 1 ke 5, serangan kamus memulihkan 0% nama (hash biasa: 100%), dan catatan bebas bersih (142 menjadi 0).
  • Hasil analisis sama: yield lini 88,3%, urutan 3 stasiun terburuk, 3 defect teratas, dan kemiringan tren (0,061 poin persentase per minggu) sama persis. Harganya resolusi: 75 titik waktu harian menjadi 15 mingguan.
  • Bisa dibalik oleh yang berhak: kode lot kembali 100% lewat mapping key; kunci dan mapping key tidak ada di repositori maupun riwayatnya.
  • Risiko yang tersisa: k-anonymity tidak melihat sel satu orang (ditutup di 225 baris) dan tidak menutup serangan penyambungan: pihak yang memegang daftar jaga mingguan menyambungkan 38 dari 39 kode ke orangnya. Indeks angka juga tidak melindungi bila satu nilai asli diketahui.

7.2 Impact

  • Nilai praktis (estimated): 45 menit per file digantikan pipeline 1 detik, sekitar 18 jam kerja per tahun bila 24 file dibagikan per tahun. Yang lebih penting dari waktu: kebijakan tertulis, sehingga tidak ada kolom yang terlewat dan keputusan bisa diperiksa.
  • Nilai analitis: hasil uji menunjukkan tiga hal yang mudah terlewat: hash tanpa kunci dipecahkan 100%, regex menyisakan 21 catatan, dan menghapus nama saja belum cukup karena stasiun + shift menunjuk satu orang.
  • Nilai portofolio: pipeline yang bisa dipakai ulang untuk membuat versi anonim data project lain (misalnya Project 3, 19, 25), lengkap dengan uji risiko, uji utilitas, dan pemindaian rahasia.
  • Belum terukur: pencocokan dengan data pihak lain yang dimiliki penerima, penerimaan oleh pemilik data pabrik, dan waktu manual sebenarnya.

  • Tutup kode operator pada sel yang hanya dikerjakan satu orang, dan jangan bagikan daftar jaga bersama data anonim. Bila penerima memegang daftar jaga, pertimbangkan membuang kode operator sama sekali.
  • Simpan kunci HMAC di tempat rahasia (bukan di repo atau kode), satu kunci per periode berbagi, dan simpan mapping key terpisah. Minta izin perusahaan sebelum membagikan data kerja.

7.5 Saran perbaikan

  • Uji pada data kerja yang sebenarnya (setelah izin) dan ukur waktu anonymization manual dengan stopwatch pada beberapa file.
  • Tambah ukuran risiko yang lebih kuat: l-diversity atau penyambungan dengan beberapa tabel penerima, dan pertimbangkan differential privacy untuk angka agregat.
  • Kenali nama orang di teks bebas dengan model pengenalan entitas sebagai lapisan tambahan di atas allowlist, dan perluas ke kolom teks lain.
  • Deploy dashboard ke Streamlit Community Cloud dan pakai pipeline ini untuk membuat versi anonim data Project 3, 19, dan 25.

7.6 Batasan

  • Semua temuan berasal dari data simulasi dengan identitas palsu dan kebocoran yang ditanam sendiri; hasil membuktikan metode, bukan kondisi pabrik.
  • Nilai k 5 berasal dari struktur data simulasi (satu baris per hari per kombinasi, operator bergilir mingguan); pada data lain k harus dihitung ulang.
  • Pseudonymization (HMAC) berbeda dari mapping key: kode HMAC tidak bisa dibalik tanpa daftar karyawan, sedangkan mapping key sengaja bisa dibalik dan harus dijaga ketat.
  • Skala angka bukan pengaman penuh: bila satu nilai asli diketahui, nilai lain terhitung. Data yang aman sendirian bisa berisiko jika digabung dengan data lain milik penerima. Differential privacy tidak dipakai.
  • Pemindai identitas hanya mengenali nama dan customer yang ada di daftar; keandalan allowlist datang dari penolakan teks yang tidak dikenal, bukan dari pengenalan nama.
  • Kunci HMAC pada simulasi dibuat acak lokal dan tidak dibagikan. Waktu manual per file dan jumlah file per tahun adalah asumsi. Dashboard belum di-deploy, dan slide (Opsional) tidak dibuat.
  • Tidak ada masalah lisensi dataset (data buatan sendiri).
